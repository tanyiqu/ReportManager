# ReportManager

ReportManager 是一款本地优先、跨平台的个人工作记录桌面应用，用于集中记录、检索、整理和导出日报、周报与每日例会内容。

应用默认使用简体中文，核心功能以离线可用为前提；业务数据保存在本机 SQLite 数据库中，不依赖账号或云端服务。首个发布版本优先支持 Windows 10/11，同时保持 macOS 和主流 Linux 的可构建、可运行能力。

## 项目状态

当前处于功能开发阶段。基础框架、本地数据层、统一报告工作区和主要桌面端交互已经完成，下一阶段重点补齐导出、周报整理和例会事项跟踪等专项业务流程。

## 当前已实现的功能

### 报告与编辑

- 支持日报、周报、每日例会及自定义报告菜单。
- 支持报告创建、读取、编辑、保存、复制和删除。
- 报告详情使用 Vditor Markdown 编辑器，支持所见即所得、即时渲染和分屏预览显示模式，并持久化用户选择。
- 报告编辑器在聚焦与非聚焦状态下均保持白色编辑背景。
- 正文以 Markdown 原文保存到 SQLite。
- 支持 `Ctrl+S` 保存、撤销/重做及 Markdown 内容复制。
- 支持报告日期修改和报告副本创建。
- 支持正文缩放，并持久化缩放比例。

### 浏览与检索

- 支持关键词搜索，覆盖标题、正文和标签。
- 支持日期范围筛选。
- 支持报告按日期倒序分页加载和滚动追加。
- 报告列表与详情区独立滚动。

### 菜单与设置

- 支持菜单显示/隐藏、排序、重命名、图标修改和报告周期设置。
- 支持自定义菜单，并将菜单配置持久化到 SQLite。
- 支持设置启动默认页面、周起始日、导出目录、报告分页数量及编辑器显示模式。
- 编辑器设置与偏好设置复用统一的表单布局和控件样式。
- 支持侧边栏展开/收起并记忆状态。
- 表单选择器、日期选择器等已接入 Semi Design。
- 设置修改后即时保存，并通过 Toast 提示结果。

### 数据与桌面能力

- 已完成本地 SQLite 数据库、参数化查询和数据库 migration 机制。
- 发布版运行时数据保存在可执行文件同级 `data/` 目录。
- 开发版数据保存在 `src-tauri/data/`。
- 支持窗口尺寸与位置恢复。
- 支持“关闭窗口时最小化到系统托盘”。
- 支持系统托盘菜单和单实例运行。
- Vditor 运行资源已本地化，编辑器无需公网 CDN。

## 核心场景

- 每日记录完成事项、进行中事项、问题风险与下一步计划。
- 按周汇总日报，整理并补充周报内容。
- 按成员记录每日例会事项、状态和截止时间。
- 按日期、关键词和标签检索历史工作记录。
- 将记录复制或导出，用于提交、分享或备份。

## 产品与架构原则

- **本地优先**：核心功能必须在离线状态下可用。
- **数据私有**：默认不上传工作内容，不要求账号登录。
- **SQLite 为业务数据源**：Markdown 文件和备份文件用于分享或恢复，不作为唯一数据源。
- **便携式数据目录**：发布版运行时数据保存在可执行文件同级的 `data/` 目录，复制程序目录即可迁移。
- **前后端边界清晰**：前端通过 Tauri Commands 调用数据、导出和设置能力，不直接访问 SQLite 或拼接 SQL。
- **兼容自由文本习惯**：保留 Markdown / 纯文本记录方式，结构化字段用于提升整理和检索能力，而非限制表达。
- **数据结构可演进**：数据库结构变更必须通过 SQLite migration 完成，并尽量保持已有用户数据可用。

## 核心记录类型

| 类型 | 用途 | 默认日期 |
| --- | --- | --- |
| 日报 | 记录当天工作进展、问题与计划 | 当前日期 |
| 周报 | 汇总一周工作及下周计划 | 当前周起始日 |
| 每日例会 | 按成员记录任务、状态与截止时间 | 当前日期 |

后续可扩展通用会议纪要、月报等类型，但不属于当前首版范围。

## 技术栈

- [Tauri 2](https://v2.tauri.app/)：跨平台桌面应用框架。
- Rust 2021：Tauri 后端、窗口、托盘和 SQLite 数据访问层。
- React 19 + TypeScript：前端界面。
- Vite 8：前端开发与构建。
- Vditor 3：Markdown 所见即所得编辑器。
- SQLite（`rusqlite`，启用 `bundled`）：本地数据存储。
- Semi Design：部分表单、选择器及日期控件。
- pnpm：JavaScript 包管理。

## 环境要求

项目当前未固定 Node.js、pnpm 或 Rust 的最低版本。开发前需要：

| 工具 | 用途 |
| --- | --- |
| Node.js | 运行 Vite 与 Tauri CLI |
| pnpm | 安装和执行前端依赖 |
| Rust stable + Cargo | 编译 Tauri 后端 |
| Tauri 2 平台依赖 | 构建桌面 WebView 与安装包 |

## 快速开始

安装依赖：

```bash
pnpm install
```

启动 Tauri 开发环境：

```bash
pnpm tauri dev
```

仅启动 Vite 前端开发服务器：

```bash
pnpm dev
```

Vite 开发服务固定使用 `http://localhost:1420`，并启用了严格端口检查。

## 构建

前端构建：

```bash
pnpm build
```

Tauri 构建与打包：

```bash
pnpm tauri build
```

仅构建便携版可执行程序：

```bash
pnpm tauri build --no-bundle
```

常规 Tauri 构建产物位于 `src-tauri/target/release/`，安装包位于其 `bundle/` 子目录。

## 数据与配置

### 开发模式

运行时数据位于：

```text
src-tauri/data/
```

主要文件包括：

- `report-manager.db`：业务数据与常规偏好。
- `config.json`：窗口尺寸和位置等启动阶段配置。

### 发布模式

运行时数据位于应用可执行文件同级：

```text
data/
```

首次运行时应用会创建需要的数据文件，并在“日报”中生成 1 条当天模拟报告（例如“8.24日报”）。该模拟数据只会在数据库文件首次创建时写入，后续启动不会新增报告。请将程序放在当前用户具有写入权限的位置。

复制应用目录及其 `data/` 目录即可迁移本地数据。

## 开发约定

1. 新功能优先符合“本地优先、离线可用、简单易用”的原则。
2. 前端不得直接访问 SQLite；数据读写统一通过 Rust / Tauri Commands。
3. SQL 查询应参数化，数据结构调整必须通过 migration 完成。
4. 发布版数据库、配置及其他运行时可变文件统一放在可执行文件同级 `data/` 目录。
5. Vditor 等运行时资源应随应用本地打包，核心功能不得依赖公网 CDN。
6. 删除、覆盖、导出及文件访问等可能影响用户数据的操作必须提供明确提示。
7. 首页和设置属于系统菜单，应始终可访问；自定义菜单及偏好需要持久化到 SQLite。
8. 记录内容保持 Markdown / 自由文本兼容，结构化字段用于增强整理和检索。
9. `clean.bat` 只清理可重新生成的构建产物和缓存，不得删除源码、配置、数据库、导出文件或其他用户数据。

## 当前首版目标

首版完成后应满足：

- 可创建、编辑、保存、查看和删除日报、周报、每日例会记录。
- 应用重启后，本地保存的数据仍完整可用。
- 可按关键词、日期、类型和标签检索历史记录。
- 可将一周日报带入周报并人工整理，且不会意外覆盖已有编辑内容。
- 可按成员维护例会事项及其状态。
- 可复制或导出单篇记录为 Markdown。
- 核心功能在断网环境下可用。

